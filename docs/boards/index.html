      Boards

      Juno compiles the same Java program for eight boards through three backends: AVR for the 8-bit UNO R3 and UNO WiFi Rev2, Thumb-2 for the Arm Cortex-M UNO R4 WiFi, UNO Q and Raspberry Pi Pico 2 W, and Xtensa for the Nano ESP32, M5Stack Cardputer and AI Thinker ESP32-CAM. Pick the target with the entry point's @Board annotation or with -Djuno.board=<id>.

      Hardware at a glance

      Boards are ordered by clock speed, then flash, SRAM and PSRAM, highest first. PSRAM is external RAM on the module, slower than the SRAM inside the chip.

      Juno never places ordinary Java objects, arrays or stacks in PSRAM. The Nano ESP32 and AI Thinker ESP32-CAM expose the static Psram byte-buffer API; the camera board also keeps its driver-owned frame buffers there behind Camera.

      The compiler checks this table for you: a program that uses an API its target board does not support fails with a CompileException naming the board and the missing capability. Some cells are compiled support that has not yet been run on every physical board; each board's page notes what is confirmed on hardware.

      Every board exposes Gpio.digitalPin("D0".."D13") and Gpio.analogPin("A0".."A5") through its board facade. The selected runtime translates those names to the board's pin mapping. getInput(), getOutput() and getInputPullup() are also board-context methods. Invalid names raise IllegalArgumentException; the M5Stack Cardputer additionally accepts its documented G* and GPIO* aliases. The Raspberry Pi Pico 2 W maps A0..A2 to its ADC pins GP26..GP28 (it has no A3..A5) and also accepts GP* and GPIO* names for its header pins. See GPIO for examples.
